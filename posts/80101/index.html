Running nginx-proxy-manager as a Reverse Proxy on Proxmox

Created2026-11-23|Updated2026-11-23
|Word Count:1.7k|Reading Time:7mins|Comments:

家里或小机房的 Proxmox 通常只有一个公网 IP，但想对外提供服务的容器却有五六个：博客、文件同步、数据库管理面板、监控。要么每个服务申请一个 IP，要么让一台机器当网关，把 80/443 收进来，再按域名分发出去。

后者就是这篇要写的方案：host 只对外暴露一个 nginx-proxy-manager 容器，所有业务容器待在内网段，域名解析到 host，由 NPM 决定流量去哪个容器。整套流程是可以复用的模板，换一台 PVE 也能照做。

一、网络拓扑

三条原则定下来，后面就不会乱：

  • 业务容器一律放内网 bridge，不给公网地址
  • host 只转发 80/443（以及可选的 81 管理口）到 NPM
  • 访问路径固定为 Internet → host:443 → NPM → 容器:端口

二、Host 侧一次性配置

2.1 打开 IP 转发

PVE 默认不开转发，容器能 ping 通 host 却出不了网，多半就是这里。

2.2 给内网段加 MASQUERADE

容器要访问外网（拉镜像、装包、申请证书），源地址必须被改写。

2.3 把 80/443 转给 NPM

最后一组回程规则别漏。少了它，包能进容器，回包却带着内网源地址直接出门，对端会丢弃，表现就是「连上了但一直不返回」。

2.4 持久化

重启后规则还在，这一点必须验证过再往下走。

四、接入一个新服务

以「把 CouchDB 反代到 couch.example.com」为例，一共三步，顺序不能反。

4.1 先确认后端监听 0.0.0.0

这是出现频率最高的 502 来源。很多服务默认只绑 127.0.0.1，NPM 从别的容器打过去自然连不上。

常见位置：

  • CouchDB：bind_address = 0.0.0.0
  • MySQL：my.cnf 里 bind-address = 0.0.0.0
  • Redis：bind 0.0.0.0 -::1
  • 各类语言服务：检查监听 host 配置

4.2 在 NPM 里加 Proxy Host

字段 填写
Domain Names couch.example.com
Scheme http（后端本身没上 TLS 时）
Forward Hostname / IP 192.168.1.20
Forward Port 5984
Block Common Exploits 建议开
Websockets Support 同步类、聊天类服务要开
SSL Request new certificate，同意 Let’s Encrypt 条款

4.3 DNS 指向 host

如果你用 Cloudflare，这条记录必须是 DNS only，别开橙色云朵。开了之后流量先到 CDN，既绕开你 host 的端口转发，Let’s Encrypt 的 HTTP-01 校验也走不通，证书申请会一直 pending。这是新手最常卡住的一步。

五、踩坑速查

现象 根因 处理
容器 ping 通 host，出不了网 没开转发或没加 MASQUERADE §2.1 / §2.2
容器地址和预期不一致 容器内 interfaces 覆盖了 PVE 设置 改完后 pct reboot
域名解析到 CDN 网段 Cloudflare 代理开着 改成 DNS only
证书一直 pending 80 没转发，或 DNS 没直指 host §2.3 / §4.3
NPM 显示 Online，实际 502 后端只听 127.0.0.1 §4.1
HTTP 能通，HTTPS 不通 443 没 DNAT，或没申请证书 §2.3 / §4.2
容器重启后临时脚本丢失 /tmp 是 tmpfs 放 /usr/local/bin/
host 上 curl 自己的公网 IP 不通 OUTPUT 链不走 PREROUTING 从外网或另一台机器测

最后一条尤其容易误判：在 host 上 curl 自己的公网地址失败，不代表转发没配好，只是因为本机发起的连接不经过 DNAT。测试要从外部发起。

六、验收清单

按这个顺序逐条过，出问题时也能立刻定位到哪一层：

  • host cat /proc/sys/net/ipv4/ip_forward 为 1
  • iptables -t nat -L 能看到对应 DNAT 与回程规则
  • pct list 里目标容器 running
  • 容器内 ip route get 8.8.8.8 网关正确，ping 8.8.8.8 通
  • 容器内 curl http://127.0.0.1:<端口> 和 curl http://192.168.1.<x>:<端口> 都返回 200
  • 外部 curl -H "Host: couch.example.com" http://203.0.113.10/ 返回 200（绕 DNS 直接测转发）
  • dig couch.example.com +short 返回 host 公网 IP
  • 浏览器 https://couch.example.com/ 200，证书有效

小结

这套结构的价值不在于 NPM 这个工具，而在于它把「对外只留一个入口」变成了默认约束：新增服务时不用碰防火墙，只要在 NPM 加一条 Proxy Host、在 DNS 加一条 A 记录。真正容易出问题的三个点，也就是监听地址、Cloudflare 代理、以及那组容易漏掉的回程规则，记住就能少走很多弯路。
